进行中「活着」· 暂停「静止」

思路反转：不给暂停态加图案，而是让进行中的条持续动，暂停时完全静止。 "停了"由对比得出——用户不需要认识某种斜纹，只要发现条不动了就懂了。 颜色按真实 dock 实测值（填充 #f9fafb 近白 / 面板深色 / 轨道透明）。

每张卡上下两行：上=进行中（动），下=暂停（静）

H · 定格（暂停时斜纹停在原处，不消失） animation-play-state: paused

暂停态要不要额外做点什么？ 如果不做，暂停就是"原条 + 静止"

这个方向的优点

  1. 零新图案：暂停态不需要斜纹/冰封/阻塞头——它只是"停下"。前面几轮讨论的"暂停该长什么样"这个问题被绕开了。
  2. 状态可瞬时感知：动/静的对比比任何静态纹理都容易被余光捕捉（人对运动敏感）。侧栏或后台切回来时尤其明显。
  3. 实现干净：动效只挂在 :not(.ss-paused) 上，暂停自动停；不需要额外 class，也不碰几何（不动 width/min-width）。
  4. 有先例：本插件 .ss-presence-ring 已用 @keyframes + prefers-reduced-motion，风格一致。
必须处理的风险
  • 持续动画 = 持续 GPU/合成开销。dock 可能同时有多条任务，若每条都在 background-position 上做动画会一起烧电。建议只让下一条要触发的那一条动，其余静止（或只保留 G2 这种 opacity 动画，可由合成器低成本处理）。
  • 无障碍：必须提供 @media (prefers-reduced-motion: reduce) 关闭全部动效（点上面的按钮可预览静止效果）。
  • 与既有动画打架：.ss-presence-ring 已在呼吸；如果再给条加动效，侧栏 + dock 会同时有多处运动，视觉噪音上升。
  • 动效"含义"要一致：G1/G6 像"数据流动"，G2 像"待机呼吸"，G3 像"推进"。选一个并保持全局一致，不要混用。
实现成本：纯 CSS 零 JSX 改动。若采纳"只让下一条动"，需要按 schedules[0] 加一个 class（ registerRow 处一行），仍属小改动。
