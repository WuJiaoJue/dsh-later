# 问题定义与目标

---

## 1. 背景

DeepSeek Harness (DSH) 是一个有持久化 session 的 AI 助手平台。用户与 agent 的对话以 session 为单位长期存在。

DSH 现有的定时能力存在三个独立方案，但没有任何一个能满足"用户在当前会话中设一个关网页也能准时触发的提醒"这个核心需求。

---

## 2. 问题陈述

### 2.1 用户真实需求

> "我在当前对话里想让 agent 10 分钟后提醒我xxx，关了网页回来还能看到。"

### 2.2 现有方案的缺陷

| 方案 | 类型 | 核心缺陷 |
|---|---|---|
| **dsh-schedule** | 官方模型工具 | 用户不能直接调，只能求模型帮设 |
| **dsh-sleep-send** | 社区 GUI 插件 | 标签页关了就死了，换浏览器就丢 |
| **Host Automations** | 官方外部调度 | 创建的是新 session，不在当前对话里 |

### 2.3 市场空白

**用户能直接操作 + 当前会话内 + 关网页也能触发 = 空白**

---

## 3. 产品目标

### 3.1 核心目标

> 在 `dsh-schedule` 底层引擎之上，提供**用户可直接操作的 GUI + 用户工具**，实现"关网页也能准时触发的会话内定时消息"。

### 3.2 具体目标

| 目标 | 衡量标准 |
|---|---|
| 用户可直接设提醒 | 无需模型参与，GUI 一键操作 |
| 关网页也能触发 | 服务端 timer 驱动，session live 即可 |
| 跨设备同步 | session 跟着用户走，换浏览器也能看到 |
| 与 dsh-schedule 兼容 | 共用事件日志，互不干扰 |

### 3.3 非目标（明确不做）

| 不做 | 原因 |
|---|---|
| 外部推送（邮件/短信） | 超出 session-local 范围，由 Host Automations 覆盖 |
| Cron 表达式 | 复杂度太高，v1 聚焦固定间隔 |
| 多 session 聚合视图 | v1 仅当前会话，v2 考虑 |
| 替代 dsh-schedule | 是扩展，不是替代 |

---

## 4. 核心用户场景

### 场景 1：长任务监控

```
用户：帮我跑这个构建，10 分钟后提醒我检查
模型：（执行构建命令）
用户：（点击 ⏰，确认 10 分钟后发送"检查构建结果"）
...
10 分钟后，对话中出现：
[SCHEDULE REMINDER] 检查构建结果
```

### 场景 2：工作流提醒

```
用户：我先去开会，30 分钟后提醒我回来继续
用户：（关网页，去开会）
...
30 分钟后，用户回来打开网页，看到：
[SCHEDULE REMINDER] 该回来继续工作了
```

### 场景 3：跨设备

```
用户在电脑前：设了 1 小时后提醒
用户关电脑出门
...
1 小时后，用户手机打开 DSH 网页，看到提醒
```

### 场景 4：等待外部事件

```
用户：PR 提交了，1 小时后提醒我看 CI 状态
...
1 小时后，对话中出现：
[SCHEDULE REMINDER] 该检查 CI 状态了
```

---

## 6. 风险

| 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|
| dsh-schedule 协议变更 | 中 | 高 | 锁定 peer dependency 版本范围 |
| 用户滥用（大量任务） | 中 | 中 | 单 session 100 任务上限 |
| 智能时段时区错误 | 低 | 中 | 强制用户选择时区，不自动推断 |
| CSS 与主题冲突 | 中 | 低 | CSS Modules / 命名空间隔离 |
