# 用户调研与场景

---

## 1. 目标用户

### 1.1 用户画像

| 画像 | 描述 |
|---|---|
| **开发者** | 长任务运行中需要提醒，编译/测试/部署 |
| **团队成员** | 需要协作提醒，PR review、会议 |
| **个人用户** | 日常提醒，待办事项、定时检查 |

### 1.2 用户痛点

| 痛点 | 严重程度 |
|---|---|
| 模型不在身边，无法设提醒 | 高 |
| 关网页就错过提醒 | 高 |
| 换浏览器提醒就丢了 | 中 |
| Host Automations 不在当前对话 | 中 |

## 2. 用户场景详解

### 场景 A：构建监控

```
角色：开发者
前置条件：正在跑一个需要 30 分钟的构建
行为：
  1. 在对话中输入构建命令
  2. 点击 ⏰ 按钮，选择"30 分钟后"
  3. 确认提醒内容："检查构建结果"
  4. 离开电脑去做其他事
  30 分钟后：
  - 如果还开着网页 → 实时看到提醒
  - 如果关了网页 → 回来打开看到提醒
预期：准时提醒，不遗漏
```

### 场景 B：会议提醒

```
角色：团队成员
前置条件：正在对话中讨论方案
行为：
  1. 说"我先去开会，30 分钟后回来"
  2. 点击 ⏰，选择"30 分钟后"
  3. 确认提醒内容："该回来继续讨论了"
  4. 关网页去开会
  30 分钟后：
  - 手机/电脑打开 DSH → 看到提醒
预期：准时提醒，跨设备可用
```

### 场景 C：定时检查

```
角色：运维/开发者
前置条件：需要定期检查服务状态
行为：
  1. 点击 ⏰，设置"每 5 分钟"
  2. 确认提醒内容："检查服务健康状态"
  3. 让它在后台运行
预期：周期性提醒，agent 自动执行检查
```

## 3. 用户旅程地图

### 3.1 首次使用旅程

```
发现插件 → 安装 → 打开对话 → 输入内容 → 点击 ⏰
    ↓
选择时间（智能时段/自定义）
    ↓
确认提醒内容
    ↓
任务创建成功
    ↓
倒计时开始
    ↓
到期触发 → 收到提醒
```

### 3.2 重复使用旅程

```
打开对话 → 看到工具行芯片（已有任务）
    ↓
点击芯片 → 查看任务列表
    ↓
可删除已有任务 / 添加新任务
```

## 4. 用户反馈收集

### 4.1 反馈渠道

| 渠道 | 方式 |
|---|---|
| GitHub Issues | bug report + feature request |
| 插件内反馈 | "导出日志" 按钮 |
| 社区讨论 | awesome-dsh-plugin.com 评论 |

### 4.2 关键问题

| 问题 | 目的 |
|---|---|
| 提醒准时吗？ | 验证触发精度 |
| 关网页后恢复了吗？ | 验证 cold session 恢复 |
| 界面直观吗？ | 验证 GUI 易用性 |
| 你需要 cron 表达式吗？ | 验证 v2 需求 |
